What tampering would look like

Editing one historical payload in the database and then re-running verification breaks the chain at exactly that sequence number, because the recomputed hash no longer matches and every downstream prev_hash pointer becomes inconsistent. The automated test suite performs this edit against a live database and asserts the break is detected. 

$ python tests/smoke.py
  PASS  modified payload breaks verification
        broken at seq 4 — recomputed hash differs
  PASS  chain verifies again after restore
Hash chaining proves the record was not altered after the fact. It does not by itself prove the sensor was honest — that requires the hardware attestation described in the operator docs.
